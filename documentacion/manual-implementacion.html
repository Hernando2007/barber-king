1. Introducción, objetivo y alcance

1. Introducción, objetivo y alcance

Descripción corta del sistema. Barber King es una aplicación móvil para Android (y preparada para iOS y Web) que conecta clientes con barberos. Permite reservar citas, consultar servicios y precios, ver el portafolio de los barberos, recibir recomendaciones de estilo con un asesor de inteligencia artificial y gestionar la agenda desde el teléfono.

Para quién es este manual. Desarrolladores, administradores técnicos y personas que deban instalar, desplegar o mantener el sistema. No es un manual de usuario final; para eso existe el manual de usuario.

Qué partes documenta. El backend (API REST en Node.js y Express), la app móvil (Flutter), la base de datos (Supabase/PostgreSQL), el almacenamiento de archivos (Cloudinary), el correo (SMTP/Brevo/Resend), el asesor de IA (Groq) y el despliegue en Render.

Objetivo. Dejar por escrito cómo está construido el sistema, cómo se instala en un equipo nuevo, cómo se despliega y cómo se mantiene, sin depender de la memoria de quien lo creó.

Alcance. Cubre la versión 1.0.0 del backend y de la app. No documenta el panel de administración de Supabase ni la consola de Render más allá de los pasos necesarios.

3. Arquitectura del sistema

3. Arquitectura del sistema

La app Flutter se comunica con la API REST de Express desplegada en Render. La API consulta Supabase para los datos, Cloudinary para los archivos, Groq para el asesor de IA y el proveedor de correo para los mensajes.

CapaTecnologíaResponsabilidad
ClienteFlutter (Dart)Interfaz móvil, lógica de presentación, almacenamiento local de sesión
APINode.js + Express 5Reglas de negocio, autenticación, validación, integración con servicios
Base de datosSupabase (PostgreSQL)Usuarios, barberos, servicios, citas, reseñas, horarios, portafolio
ArchivosCloudinaryFotos de perfil, portafolio, diplomas, imágenes del chat
IAGroq (openai/gpt-oss-20b)Asesor de estilo y análisis de diplomas
CorreoNodemailer + SMTP/Brevo/ResendBienvenida, recuperación de contraseña
ErroresSentryReporte de excepciones (opcional)

Flujo de una reserva. El cliente elige servicio y barbero en la app → la app llama a /api/citas/crear con el token JWT → la API valida el horario libre contra la jornada del barbero en Supabase → se guarda la cita con estado Confirmada → el barbero la ve en su agenda.

6. Modelo de datos

6. Modelo de datos

La base de datos es PostgreSQL en Supabase. Las tablas principales son:

TablaDescripción
usuariosCuenta: nombres, apellidos, correo, teléfono, fecha de nacimiento, rol, estado, avatar, google_id, vip
rolesAdministrador (1), Barbero (2), Cliente (3)
barberosPerfil profesional: especialidad, experiencia, descripción, dirección, verificación, ubicación, calificación
serviciosCatálogo: nombre, descripción, precio, duración, imagen, estado
barbero_serviciosQué servicios atiende cada barbero y con qué precio y duración propios
citasReserva: cliente, barbero, servicio, fecha, hora, estado, observaciones, precio
horariosJornadas de trabajo por barbero y día de la semana
disponibilidadHoras libres calculadas para un barbero en una fecha
resenasCalificación y comentario por cita completada
portafolioFotos de trabajos del barbero (hasta 24)
verificacionesEstado de revisión del diploma del barbero
avisosNotificaciones y novedades para los usuarios
mensajes_chatHistorial del chat con el asesor de IA (texto e imágenes)

Las relaciones principales: un usuario tiene un rol; un barbero pertenece a un usuario; una cita vincula cliente, barbero y servicio; una reseña pertenece a una cita. Supabase aplica Row Level Security (RLS) para que cada usuario solo vea sus propios datos.

8. Seguridad

8. Seguridad

  • Autenticación. JWT firmado con JWT_SECRET, expiración de 8 horas. El token se envía en el encabezado Authorization: Bearer.
  • Contraseñas. Hash con bcrypt (costo 10). Nunca se guardan en texto plano.
  • Google Sign-In. El idToken se verifica con google-auth-library contra los clientes permitidos. La audiencia debe coincidir o ser del mismo proyecto.
  • Roles. Middleware verificarRol restringe rutas por rol (Administrador, Barbero, Cliente).
  • Row Level Security. Supabase aplica RLS para que cada usuario solo acceda a sus datos.
  • Cabeceras. Helmet desactiva x-powered-by y configura CSP y CORS.
  • Límites. Rate limiting general y específico en login, registro y recuperación de contraseña.
  • Llaves. El keystore de subida (upload-keystore.jks) y key.properties no se versionan. Se guardan fuera del repositorio.
  • HTTPS. Todas las comunicaciones entre la app y el backend van cifradas. Render provee el certificado.

10. Instalación local y despliegue

10. Instalación local y despliegue

Backend en local

  1. Clonar el repositorio y entrar a backend/.
  2. Copiar .env.example a .env y completar las variables.
  3. Ejecutar npm install.
  4. Ejecutar npm run dev (nodemon) o npm start.
  5. Verificar en http://localhost:3000/health.

Pruebas

Ejecutar npm test en backend/. Usa el runner nativo de Node (node --test).

App en local

  1. Entrar a frontend/barber_king_app/.
  2. Ejecutar flutter pub get.
  3. Ejecutar flutter run (emulador o dispositivo conectado).
  4. Para usar el backend local, cambiar useRemote a false en api_config.dart.

Despliegue del backend en Render

  1. Conectar el repositorio en Render.
  2. Configurar las variables de entorno del .env.example en el panel de Render.
  3. Comando de inicio: node index.js (o npm start).
  4. Render despliega automáticamente al hacer push a main.
  5. Verificar en https://barber-king.onrender.com/health.

Compilación del AAB (Android)

  1. Verificar que exista android/key.properties con la llave de subida.
  2. Ejecutar flutter build appbundle --release.
  3. El AAB queda en build/app/outputs/bundle/release/app-release.aab.
  4. Verificar la firma con keytool -printcert -jarfile app-release.aab (SHA-1: 9A:6C:C5:89:DE:75:35:19:5F:C9:1C:51:BE:43:36:3E:DA:58:F3:82).
  5. Subir el AAB en Play Console.

11. Mantenimiento

11. Mantenimiento

Cómo agregar una función nueva

  1. Crear la ruta en backend/routes/ y el controlador en backend/controllers/.
  2. Agregar el modelo en backend/models/ si necesita acceso a Supabase.
  3. Registrar la ruta en app.js.
  4. En la app, agregar el servicio en lib/services/ y la pantalla en lib/screens/.
  5. Ejecutar npm test y flutter analyze antes de subir.
  6. Hacer commit y push a main; Render despliega automáticamente.

Errores conocidos

ErrorCausaSolución

Correo no se envíaSMTP mal configuradoVerificar SMTP_HOST, PORT, USER y PASS
App no conecta al backenduseRemote en false o URL incorrectaPoner useRemote en true en api_config.dart
Código de versión duplicado en PlayversionCode ya usadoSubir el número después del + en pubspec.yaml

Dónde ver los logs

  • Backend: panel de Render → Logs, o consola local con npm run dev.
  • App: flutter run en consola, o Sentry si está configurado.
  • Base de datos: panel de Supabase → Logs y Table Editor.
